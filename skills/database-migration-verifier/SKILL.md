# Database Migration Verifier & Schema Safety Skill

## Overview
Ensures that all database schema migrations generated by AI agents (Prisma, Drizzle, Alembic, raw SQL) follow the expand-contract zero-downtime migration protocol without locking production tables.

## 4 Rules of Zero-Downtime Migrations

### 1. The Expand-and-Contract Pattern
* NEVER rename or delete an active column in a single migration.
* **Phase 1 (Expand)**: Add the new column as nullable (`ALTER TABLE products ADD COLUMN retail_price NUMERIC NULL;`).
* **Phase 2 (Dual-Write)**: Application writes to both old and new columns.
* **Phase 3 (Backfill)**: Run async background worker to backfill data.
* **Phase 4 (Contract)**: Drop old column in a subsequent release.

### 2. Avoiding Full Table Locks on Large Tables
* In PostgreSQL, avoid adding columns with non-constant defaults without `DEFAULT ... NOT NULL` on older engines.
* Add indexes concurrently:
  ```sql
  -- Bad (Locks table writes during creation):
  CREATE INDEX idx_products_sku ON products(sku);

  -- Good (Zero-downtime concurrent indexing):
  CREATE INDEX CONCURRENTLY idx_products_sku ON products(sku);
  ```

### 3. Safe Foreign Keys with Deferred Validation
* Add foreign keys with `NOT VALID` first, then validate separately to avoid holding exclusive table locks.

### 4. SQLite WAL Mode & Timeout Safeguards
* For SQLite databases (e.g. `price_tracker.db`):
  - Always enable WAL mode: `PRAGMA journal_mode = WAL;`
  - Set busy timeout: `PRAGMA busy_timeout = 5000;`
